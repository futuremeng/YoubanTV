# AGREE —— 约定怎么立

约定是这个产品的中心物件：**装完应用第一次打开要做的事，就是把一份约定立起来**；
除此以外的东西（授权、探针、出网、配对）都是可选的、未完成只降级（`ONBOARD-06`）。
本页只回答三件事：一条约定长什么样、由谁签哪一条、什么时候生效。字段与默认值的**数据**在
[`../contract/contract.json`](../contract/contract.json) 的 `agreement` 一节（D45：一类规则只留一处），
流程与界面写意在 [`../docs/AGREEMENT.md`](../docs/AGREEMENT.md)。

### AGREE-01 初始化就是建立约定
首次打开应用的必做项只有「立一份约定」（六步，见 AGREE-05）。引导页**不请求与约定无关的权限**；
设备条目（悬浮窗、使用情况访问、探针）在「设备」页按需要再问，未确认只降级不阻断（`ONBOARD-06`）。

### AGREE-02 一条约定的形状
一条约定 = `(字段, 取值, 类别, 生效路径, 签署记录)`。签署记录即
`PLAN_SIGNED(profile, version, by:[self, counterparty])`（`AUTO-07`）。界面上任何一条都要能答出：
这条是给谁的、谁签的、什么时候签的、依据哪个条目（AGREE-12）。字段与类别的清单在契约 `agreement.fields`。

### AGREE-03 三类条目，各自的确认人
| 类别 | 谁写 | 生效条件 | 未完成时 |
|---|---|---|---|
| 共意（`joint`） | 双方，经 `ruleEditor` 编辑权（`AUTO-07`） | 双方签署（`AUTO-04`） | 不生效，按上一份或默认跑（AGREE-06） |
| 自管（`self`） | 本人，与强度与角色无关（`AUTO-14`） | 写入即生效 | — |
| 设备（`device`） | 当前激活成员 | 授权/探针通过 | 取该能力最保守的可用档并写明原因（`ONBOARD-06`） |

### AGREE-04 默认值先跑起来，界面写明「默认·未签」
装机后先按契约 `agreement.defaults`（按受众 × 日型）跑（`DAY-03`）。默认值**不是**约定的一部分，
不进签署记录；界面上被默认填着的条目标「未签·默认」，只在状态句里说一句，不弹催签、不进那一页的账（`REPORT-02`）、
不打分、不做连续天数（`ONBOARD-05`、AGREE-10）。

### AGREE-05 首启的六步
按契约 `agreement.firstRun` 的顺序：命名与内容绑定 → 受众 → 约定三段（每天使用时长 / 约定线 /
运动段起点）→ 时段与免题段 → 委托强度 → 双方签署。一步一项，一步都不 blocker：
每一步都可以「先用默认」（`agreement.firstRunEscape`）。六步走完写 `PLAN_SIGNED(v1)`；
中途退出也允许，此时按 AGREE-06 的状态跑。
**按默认的那一步必须写明去哪儿改**（`agreement.firstRun[].where` + `agreement.ui.defaultsWhere`）：
屏上不许只留「按默认」三个字——看不清去哪儿改的默认，等于把选择悄悄收走。

### AGREE-06 「还没签」不是一个罪名
未签署的版本不进运行版本、不写 `PLAN_SIGNED`（`COMMIT-08`、`AUTO-04`）；界面状态句说明
「这一份还没签，按上一份跑」；**不把「没签」记成某个成员的违规**，不进任何统计（AGREE-10）。

### AGREE-07 改约定 = 动议 + 签署，生效路径只有一条
对已签条目的改动先进入「待对方受理」（`AUTO-03`），再走双方签署。**收紧**（约定线调低、免题段调小、
运动段提前、时段变窄）自下一份签署生效（`AUTO-04`、D37）；当日生效路径：增大当日生效、减小次日生效（D37）。
临时加时不是改约定，是当日约定线的偏移（`extend`，`AUTO-03`）。

### AGREE-08 切换身份就是换一组约定
约定按身份各立一组。`PROFILE_SWITCH(from, to, at)` 之后加载**那一组**的生效版本、字段与签署记录
（契约 `agreement.perProfile`）。两组约定互不影响：一份的收紧不会改掉另一份；共意条目的对方可以不同。
当前生效的约定版本在角标旁常驻可见（`PROFILE-05`）。

### AGREE-09 切到一个还没有约定的身份
该身份没有已生效的约定 → 走 AGREE-05 那六步，**但设备条目不重复问**（授权与探针结果按设备复用）。
已有 → 直接加载，不再问。被他人代填的字段仍受编辑权与自管规则约束（AGREE-03、`AUTO-14`）。

### AGREE-10 约定里不许出现的字段
见契约 `agreement.never`：时长兑换题目（D24、D31）、签到/连续天数/徽章/递进催促（D31）、
把「父母」写成特权身份（D33）、把「未签」记成违规（AGREE-06）、装机默认全开设备条目或出网
（`ONBOARD-06`、`ONBOARD-08`）。契约引用门会卡禁止字段。

### AGREE-11 收回与撤销
任一方可随时提「收回委托 / 收回编辑权」动议；**把别人手里的编辑权收回来属收紧**，自下一份双方
签署生效（`AUTO-04`、`AUTO-09`）。出网开关与数据保留由 `keyHolder` 当场再认证后再改（`ONBOARD-08`）。
约定里任何一条都可以被提「停止提示」动议临时静默（`stopHint`，`AUTO-03`）。

### AGREE-12 每个成员都能看全自己受哪几条例约约束
界面一处列出：生效条目 + 版本 + 签署人与时刻 + 该条依据的条目 id + 下一步（AGREE-02）。
导出「我的数据」时这一节一并导出（`ONBOARDING.md §6`、`PRIVACY.md §1`）。

### AGREE-14 约定是可查阅的，查阅面不带任何推力
每台设备都要有一屏能回答：这一档现在按哪几项跑、这一份是谁在什么时候签的；没签就写「还没签 ·
按默认跑」并指向立约定那一步。这一屏**全是只读**：没有按钮、没有红点、没有催签、没有完成度，
条目再多也不组成清单或分数（`AUTO-14`、`ONBOARDING.md §5`）。签署时刻取自事件账那一条
`PLAN_SIGNED`，界面上不另算一份。

### AGREE-13 换设备与重装
约定属于家庭账本，不属于单台设备：新设备加入时读同一份账，读不到就按 AGREE-04 的默认档跑并写明
「这台机器还没读到已签署的约定」。设备条目按新设备重新探（`ONBOARDING.md §4`）。
