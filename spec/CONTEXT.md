# CONTEXT —— 伴看上下文（默认关）

这是本项目**唯一**会读取「正在看什么」的能力。它放宽了 `AUTO-11` 的默认面，因此每一条都必须可核查。

### CONTEXT-01 开关与说明
`capability.companionContext: off | titleOnly`，默认 `off`。开启界面直接写三句话：
「开启后只取当前前台窗口的标题」「标题只留在内存，不落盘」
「若同时启用 AI 出题，标题会发往 `<host>`，该地址由 `keyHolder`（监护人凭据持有者，`AUTO-10`）填写」。

### CONTEXT-02 取值范围
- 取法：`UsageStats` 的最近活动**标题文本**（已有的使用情况访问授权范围内），一次只取一条，用完即弃。
- 取值面之外：截屏、录屏、屏幕 OCR、音频指纹、按键记录、URL/播放列表抓取、应用使用清单落盘。
  CI 门扫这些 API 名，出现即红。
- 标题**不写进任何表**；面板不得显示「刚才在看 X」；诊断日志里出现标题即测试红。

### CONTEXT-03 出网条件
`companionContext=titleOnly` **且** 启用 AI 出题 → 标题作为提示词一部分发往 `keyHolder` 配置的 host。
这条进 `PRIVACY.md §2` 的网络清单与数据表，并在**每次**出题时把用到的上下文显示在题目角落
（「依据：当前节目名称」）。上下文不得用于出题以外的任何用途（不得进批改提示词、不进那一页的账（`REPORT-02`））。

### CONTEXT-04 上下文只是可选提示词素材
出题的主依据始终是**身份的内容绑定 + 知识大纲 + 履约历史**（`PROFILE-06`）。
标题缺失、无信息量（「首页」「直播」这类）或被排除时，按大纲出题。

### CONTEXT-05 上下文题的机检
结合上下文出的题必须有可机检的 `verify`（求值语义见 `content/verify`），机检不过 → 不出、不入库，
记 `llm_generate_failed`。`ambient` 题另受 authoring 门禁：题干 ≤30 字、选项 ≤2 行、单键可答。
上下文题必须**在看的内容里能找到依据**；离线校验不过就退回大纲题。

### CONTEXT-06 呈现时机的取值
- `onDemand`（用户喊「出题」）与 `timed`（每 N 分钟一条）：首发提供。
- `atPausePoint`（自然停顿点，靠广告/场景切换信号）：实验特性，默认关，范围外于首发；
  信号不可靠时取 `timed`。

### CONTEXT-07 可核查、可撤回
- 「我的数据」页与面板「隐私与出网」页显示：开关状态、出题依据的来源类别（来源类别与开关状态两项，含标题的
  内容不出现在页面上）。
- 关闭开关即停止取值；此前已发往 AI 服务的内容按该服务的数据政策处理，关闭提示里写明这一点。
- 每次开关变更写审计事件（谁、何时、从哪档到哪档）。
