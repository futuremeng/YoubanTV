# AUTO —— 自主性条目

### AUTO-01 结论可解释
每条结论都带 `ruleId` + `deficit` + `nextAction` + `window`（结构见 `ARCHITECTURE.md §9`），缺一即测试红。
文案语气随当前层走（`LAYER-09`）：**已受理的动议**走 L1.5，用状态句给出当前状态与恢复时刻；做题与运动的
约定按 `LAYER-07` 的默认档呈现，给出约定、差多少、下一步。

### AUTO-02 一本账两份视图
本人端与家庭面板的账本是同一份投影，字段集合相同。私密项（监护人凭据本体与 AI 密钥、其它设备清单）
在任何主体的可读范围之外，只有 `keyHolder` 当场操作时可见其「是否已配置」。

### AUTO-03 动议与受理（即时控制与旧「申诉」同一机制）
对约定的临时变更一律是**动议**：提出方、对象、条款、一句理由；对方一次受理（接受或婉拒，都附一句理由）。
本人发起的动议就是旧称的「申诉」，成员发起的动议就是曾经的「即时控制」——两套叫法，一套机制。

| kind | 端点 | 发起方 | 配额（每人每天） | 受理后的效果 |
|---|---|---|---|---|
| `pause` 暂停 / 解除暂停 | `POST /api/motions` | 任一成员 | 3 次 | 状态与提示变更，`pauseMs` 单列记账（`COMMIT-07`） |
| `extend` 临时加时 | 同上 | 任一成员 | 2 次，每次 ≤15 分钟 | **当日约定线的偏移**，不改 `dayPlan` 本身；写 `PLAN_CHANGE` |
| `stopHint` 停止本机提示 | 同上 | 该身份自己 | 1 次 | 即时生效（只影响自己的呈现） |
| `cancelTask` 免做本次任务 | 同上 | 本人 | 1 次 | 只跳过本次任务，当日剩余目标不变 |
| `changeTask` 换任务形式 | 同上 | 本人 | 1 次 | 由**未参与该项的一方**从候选里选或自填 |
| `slotChange` 时段微调（当天内） | 同上 | 任一成员 | 1 次 | 当日时段偏移，次日按 `dayPlan` 恢复 |
| `planChange` 改规则 | 同上 | `ruleEditor`，或自管强度下的本人 | 不限 | 产生新 `planVersion`，按 `AUTO-04` 生效 |
| `dataExport` 导出数据 | 同上 | 本人 | 不限 | 生成可读文件 |
| `coWatch` 共看邀请 | 同上 | 任一成员 | 不限 | 受理后两台设备显示同一状态条（`MOBILE.md §2`） |
| `roleChange` 角色的移交与收回 | 同上 | 角色持有人 | 不限 | 对方在自己界面受理即换人；收回属收紧，自下一份签署生效（`AUTO-09`） |

每条写 `MOTION(kind, by, at, terms, reason)` 与 `MOTION_SETTLED(accepted, reason, at)`；两侧账本都留行。
每台设备都要有一屏把这串历史**只读**地摆出来（谁提的、什么时候、哪一种结果；
婉拒与接受是同一条事件，「没人受理」是另一条），这一屏上没有受理的按钮。
**受理面只有一个：被请求方自己的界面**（对方的模式或对方的设备）；不存在代为受理与双方同时在线的路径
（`PROFILE-10`）。动议有效期默认 24 小时，超时写 `MOTION_UNANSWERED`，不自动重发，30 分钟冷却后可再提。
配额对**所有成员同量**；婉拒后同类动议冷却 30 分钟，防止刷屏（`SENSE-07` 同一思路）。
获批的加时不发放额外时长，只把当天约定线往后推相应分钟。

### AUTO-04 收紧自下一份签署生效
任何收紧（约定线调低、免题段调小、运动段提前、时段变窄）在下一次双方签署前不生效；
放宽立即生效。比较基准是任务快照。界面写明生效时刻。
**跨零点的边界（D37）**：收紧在跨零点前 5 分钟内产生时，顺延至**次日零点后**生效；已受理的当日偏移
（`extend`）不算收紧，不受此限。
**自管字段（`AUTO-14`）不进入收紧比较**：该身份自己改组数、每组题量与补一补节奏，即时生效并写
`PLAN_CHANGE` 留痕，无需对方受理。

### AUTO-05 反 dark pattern
文案只使用状态句与下一步；激励来源是任一家庭成员写的句子（来源标注到人）与自己的进度曲线。
成就、连击、排行、称号、签到、徽章这类机制在功能范围之外。
错误提示必须给出下一步；取消与退出路径一步可达；说明放在常驻位置。

### AUTO-06 每个身份的界面与数据权利
- `GET /api/me`：账本视图（与面板同源）+ 当前协商强度 + 当前层 + 伴看上下文开关状态。
- 可见范围：进度与掌握情况、生效的约定条目、自己的动议与受理记录、数据存放位置与保留时长、出设备的条件。
- `POST /api/me/purge`：清除自己的记录，家庭协议与他人账本各自独立，写一条审计事件。
- 导出：`MOTION(kind=dataExport)` 受理后生成可读文件；`ruleEditor` 与 `keyHolder` 可代为发起，但文件内容
  只含本人数据。

### AUTO-07 协商强度是委托程度，不是身份差别
三档强度描述的是**约定字段编辑权握在谁手里**，由每个身份自己选，切换强度时功能集合保持不变（`PROFILE-03`）：

| 强度 | 约定字段编辑权 | 到期项默认档 |
|---|---|---|
| 陪伴式 | **委托**给另一位成员（`ruleEditor`）：可轮值、可随时收回、全程留痕 | L3 |
| 协商式（默认） | 双方共同持有，周计划双方签署 | L2 |
| 自管式 | 完全由该身份自己持有 | L1 |

- 协商式的周计划需双方签署：`PLAN_SIGNED(profile, version, by:[self, counterparty])`；未签署的计划不生效；
  改动已签署的计划进入「待对方受理」，受理前旧计划继续生效。
- 无到期项时的状态层（L1 / L1.5）与强度无关（`LAYER-02`）。
- 委托关系写在协议里而不是身份里：任何一档下所有功能对所有身份同样可见（`PROFILE-03`、I2）。
- **自管式下 `dayPlan` 的可写范围（D39）**：`allowance` / `grace` / `moveFrom` 归该身份写；`slots` 与家庭
  协议字段**仍属双方**（时段影响设备与其他成员）；自管四项始终可写（`AUTO-14`）。

### AUTO-08 强度与呈现层的一致性
强度与层的合法组合由 `LAYER-07` 定义，配置界面只提供合法组合；落层规则见 `ARCHITECTURE.md §9`。
自管强度下把呈现升到 L3 是合法组合，界面写明「题目会请求暂停播放，答完恢复；本机不支持时自动转
`ambient`」（F12）。未知情升档时，自管强度下的 `focused` 任务按 `ambient` 呈现。

### AUTO-09 收回与轮值留痕（本机当场，不需要同时在场）
角色的交接不是开会，而是**单用户场景下的两次确认**（`PROFILE-10`）：持有人在自己的模式里提一条
`roleChange` 动议，对方在自己的界面里一次受理即换人。

- 交回与放宽即时生效；**把别人手里的编辑权收回来是收紧**，自下一份双方签署生效（`AUTO-04`）。
- `keyHolder`（监护人凭据）的移交必须在**被控设备本机**由现任当场确认，不接受远程受理；
  这是唯一需要现场动作的角色变更（`PRIVACY.md §6`）。
- 每次变更写 `ROLE_CHANGE(role, from, to, at)`；收紧时 `planVersion` 上升。变动记录在本人端与面板两侧
  同样可见，只追加不改写；界面上常驻显示当前持有人。
- 收回自管强度同样按 `AUTO-04` 处理；委托与收回都不是身份变动（`PROFILE-01`）。

### AUTO-10 主体与角色（契约层无「一类人」）
- 主体一律是 `member:<id>`——家庭成员同一主体，没有天生的特权身份（D33）。
- 权力是**角色**：`roles: [ruleEditor, keyHolder]`，由家庭协议授予与收回（`AUTO-09`）。同一时刻每类角色
  各只有一人持有，可轮值；每类角色的**写入口只在本机当前激活模式内**，面板与其他设备只能读（`PROFILE-10`）。
- 端点对所有成员同一语义：`GET /api/me`、`PUT /api/myPlan`、`POST /api/me/purge`、`POST /api/motions`。
  角色的移交走 `roleChange` 动议，不另设 `/api/roles` 这类跨主体写入口。
- 可读：自己账本、生效约定、待受理动议。可写：动议；自管字段（`AUTO-14`，与强度无关）；主观题自评结果
  （`AUTO-15`）；自管强度下写自己的计划。
- 只有 `ruleEditor` 可写约定字段（`AUTO-07`）；只有 `keyHolder` 可开关出网路径与设数据保留天数
  （`AUTO-15`、`PRIVACY.md §6`）——保留天数与出网属同一个隐私域，不归 `ruleEditor`；开关变更需当场
  再认证（D38）。
- 可读范围之外：监护人凭据本体与 AI 密钥、其它设备清单、诊断日志。`protocolVersion` 覆盖主体与角色字段。

### AUTO-11 前台取值
`enforcement` 向内核报告 `isControlledContent: Boolean` + 时长；内核与事件账的字段集合里没有包名与
应用名（CI 门）。
开启伴看上下文后额外取当前前台窗口的一条标题：一次一条、只在内存；仅在启用 AI 出题时作为提示词素材
发往该 host，并在题目角落显示依据。画面与声音的取值由 CI 门按 API 名单校验（`CONTEXT-02`）。
本条把默认取值域从「布尔 + 时长」扩展为「布尔 + 时长 +（可选）一条前台标题」，扩展部分是配置项。

### AUTO-12 界面与机制只服务于约定本身
规则可解释、文案是状态句、每次呈现给出下一步——目标是使用者无需猜测规则即可安排自己的时间。
规避检测类功能（隐藏窗口、隐蔽监控、静默收集）在功能范围之外，配置项亦然。

### AUTO-13 激励的取值范围
激励只有三类：星与掌握进度（自己的记录）、当日账目的可见与入账（`WATCHED` / `OVER` / `DONE` 的呈现）、
「这段时间的账」那一页与成长记录（`REPORT-01..04`）。时长不因做题或运动而发放：激励与观看权限之间的耦合关系在契约里无定义。

### AUTO-14 学习参数由该身份自己设定（自管字段）
自管字段只有四项：组数（`DAY-05`）、每组题量、每次任务的题目数上限（`ASK-07`）、
补一补是否先补完（`ASK-04`、`LAYERING.md §2` 场景 6）。

- **一律由该身份自己设定**，与协商强度档位无关、与 `audience` 无关（陪伴式下同样由本人设，`PROFILE-02` 的
  CI 门同样适用）；写入走 `PUT /api/myPlan`，即时生效。
- 面板与其他成员对这四项**只显示当前值与改动记录**，不得提供修改入口，也不得加强制门；
  不同意的做法是提一条动议或走家庭协议（`AUTO-03`）。
- 约定线、免题段、运动段起点与时段仍是规则字段：按委托关系与签署规则定（`AUTO-04`、`AUTO-07`）。
- 面板与本人端显示同一份值（`AUTO-02`）；自管字段的每次改动写 `PLAN_CHANGE`，事后能回答「当时按哪组参数出的题」。
- 测试：`fixtures/profile.yaml#AUTO-14`（三档强度下均只能由本人写入；面板写入路径不存在）

### AUTO-15 批改与确认是「查阅与修订」
默认由本人先把账做完，其他成员的动作只有两个：**查阅**与**修订**。

- 主观题由激活身份自己对照评分标准自评，**先入账**（星与掌握进度），结果标注 `gradedBy=self`；
  启用 AI 批时同样先入账，标注 `gradedBy=ai` 并以待查阅的姿态呈现。
- 查阅是只读动作，不阻塞入账；面板与本人端看到同一份判定（`AUTO-02`）。
- 修订即改判：附理由、写 `REVISION(target, by, reason, at)`，星与掌握进度按修订后的判定重算；
  理由与历史在本人端与面板两侧同样可见（与 `AUTO-03` 一套留档规则）。
- 修订只改账目判定，**不改变 `status` 的算法**（它只按事件与约定算）；「先批完才入账」这类开关不存在。
- 设备动作同理：更新由**激活身份查阅更新说明后安装**，其他成员只有查阅与回退（留痕，`D17`）。
- **边界**：把题干 / 答案 / 图片发往外部 host 的开关仍由 `keyHolder` 显式开启（`PRIVACY.md §6`、`AUTO-10`），
  不在自管范围内；查阅与修订本身只在局域网内，不新增出网路径。
- 与 `audience` 与协商强度无关；测试：`fixtures/commit.yaml#AUTO-15`（自评入账不依赖他人参与；
  修订后星与掌握重算；修订事件与理由两侧可见）

### AUTO-16 动议不得单方面生效
- 对**他人**的约定或设备状态的任何改变，都必须经动议受理（`AUTO-03`）才生效。不存在单方面生效的路径：
  CI 门要求 `enforcement` 的接口面只有 `present()`，任何 `pause(profile = <他人>)` 形态的 API 在 `core` 与
  `device` 中出现即红（与 `COMMIT-10` 同一道门）。
- **超时未受理 = 不生效**：默认 24 小时（`AUTO-03`）后写 `MOTION_UNANSWERED`，双方账本各留一行；
  不得以「对方没看到」为由先行执行。单用户场景下这就是默认形态：对方下次打开自己的界面时才受理
  （`PROFILE-10`）。
- 只对**自己**生效的动作可以即时执行：停止自己的提示、暂停自己的计时会话、结束自己的任务。
- 动议不能命令外部设备断电或切源：L5 只由**已签署的时段规则**触发（`COMMITMENTS.md §5`）。
- 动议的呈现只用 L1 一条提示（可忽略）与受理后的 L1.5 状态句；不请求播放器暂停、不占用浮层、
  不发系统通知（`LAYER-10`）。
- 测试：`fixtures/commit.yaml#AUTO-16`（未受理不生效；单方面控制 API 不存在；婉拒后冷却 30 分钟生效；
  动议不能触发 L5）

### AUTO-17 共看、在场提示、家人原话这三样不做
- 设备之间的关联**只有体感中继与视觉中继两件事**（`SENSE-06`、`DAY-10`）。除此之外**没有设备间的消息通道**：
  契约里既没有 `POST /api/cowatch`，也没有 `POST /api/messages`（两条都登记在 `retired.endpoints`，出现即红）。
- **共看安排与共看邀请不做**：动议种类里没有 `coWatch`（`motion.kinds`），`dayPlan.slots` 里没有 co-watch 这类段，
  面板里也没有那一页（`PANEL-01`）。
- **在场提示不做**：一台设备不把「某人独自看了多久」发到别人的设备上——`SENSE-06` 那条 `never` 清单里的
  「另一台的账本」正是此事。「一起看了多久」这个对偶量因此没有来源，**不做**（原 `COMMITMENTS.md §4b` 划出范围；
  依据侧的张力见 `D79`）。
- **家人原话的送达不做**：家人写的句子仍然**标注到人**（`LAYER-09`——谁写的就署谁），但**撰写入口是面板**，
  本项目不做设备之间的送达，也不做「妈妈写的」那类推送。
- **伴看上下文**（`CONTEXT-01..06`、`egressSwitch.companionContext`）**不属于这三样**：它是出题素材的一条出网开关，
  与设备协同无关，照旧默认关。
- 测试：`fixtures/commit.yaml#AUTO-17`（两条端点不存在；动议种类里没有共看；在场形态那一档没有取值表；
  面板的页表里没有共看那一页）
