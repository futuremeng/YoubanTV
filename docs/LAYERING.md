# 分层策略（Layering）

每个能力**默认停在哪一层、怎么升层、怎么退回来**——这一篇是唯一答案。层描述**侵入度与呈现时机**；
许可与阻断属于已退役的旧模型，当前代码只呈现与记录。

## 1. 层

| 层 | 名字 | 对用户做了什么 | 影响谁 | 需要的授权 |
|---|---|---|---|---|
| **L0** | 观察 Observe | 记录与呈现 | 无人 | 无 |
| **L1** | 提示 Nudge | 在恰当位置说一次，可忽略 | 当前使用者 | 无 |
| **L1.5** | 状态提示 Status nudge | 持续状态提示：常驻提示条 + 顶栏角标 + 一次通知；点开给详情与动议 | 当前使用者 | 无 |
| **L2** | 应用内约定 In-app rule | 在本应用内安排流程与题目呈现时机 | 当前使用者 | 无 |
| **L3** | 应用外呈现 Out-of-app | 悬浮角标与浮层、前台计时：离开本应用仍可见 | 当前使用者 | 悬浮窗 / 使用情况 |
| **L4** | — | 编号保留，当前设计里无内容 | — | — |
| **L5** | 外部协同 External | 由外部设备执行：智能插座断电、HDMI-CEC 切换、路由限速、Home Assistant | 由外部设备决定 | 外部设备配对 |

四条规矩：

1. **默认停在最软的够用层**——分两条线，各自唯一，不互相覆盖：
   - **状态层**（此刻没有到期项）：只有角标剩余与**待受理动议**（一条提示）时为 **L1**；存在需要持续可见
     的状态（`overdue`、**已受理的暂停**）时为 **L1.5**。这一条与协商强度无关，也就是「默认停在 L1.5」
     真正适用的那几种情形。
   - **到期层**（此刻有 `due`）：由协商强度取默认档——陪伴式 L3 / 协商式 L2 / 自管式 L1（§3）。
     落层 = min(`tierFor` 的形态首选层, 该档)；默认档高于形态首选层时不上抬，而是默认开启 L3 的
     应用外呈现通道（`ARCHITECTURE.md §9`、`LAYER-07`）。
2. **升层是显式动作**：一次点击 + 一句「这一层做什么、代价是什么、怎么退回来」。入口带 `revertPath`。
3. **措辞跟随层**（§4），界面只描述当前实际层的能力。
4. **手机端只用应用内呈现**（L1 / L1.5 / L2；L2 的题目呈现时机也在应用内），系统悬浮窗与开机广播这两个
   L3 触发器只在电视装配里用（`MOBILE.md §4`）。

（`ARCHITECTURE.md §9`）。

新增能力必须先在表里占一行：在哪一层、默认层、上面还有哪层。答不上这三问的能力留在文档阶段。

## 3. 协商强度给层的天花板

强度定天花板，天花板内取**到期项的默认档**（陪伴式 L3 / 协商式 L2 / 自管式 L1）；无到期项时的状态层
与强度无关（§1 规矩 1、`LAYER-02`）。强度由每个身份自己选择，对所有身份是同一张矩阵：

| 协商强度 | L0–L2 | L3 | L4 | L5 |
|---|---|---|---|---|
| 陪伴式 | ✓ | ✓ 默认 | — | 需配对 |
| 协商式（默认） | ✓ 默认 L2 | ✓ | — | 需配对 |
| 自管式 | ✓ 默认 L1 | ✓ 默认，界面写明「题目会请求暂停播放，答完恢复；本机不支持时自动改为 `ambient`」 | — | 需配对 |

## 4. 措辞规则

| 层 | 语气 | 例句 |
|---|---|---|
| L0 / L1 | 告知 + 一次建议（不承诺兑换） | 「今天已看 26 分钟，约定 60 分钟。有一组题待做，现在做吗？」 |
| L1.5 | 状态 + 恢复时刻 | 「已暂停 8 分钟，19:40 自动恢复。今天还剩 12 分钟，已按约定使用。」；`overdue`：「超出约定 12 分钟。」 |
| L2 | 约定 + 下一步 + 窗口期 | 「这一组答完（5 题、对 4 题）就记为已完成。19:00–21:00 内都算今天。」 |
| L3 | 状态 + 状态来自哪条约定（呈现到应用外，不阻断观看） | 「今天的约定是 60 分钟，已用 72 分钟。明天 00:00 重新计时；也可以按约定申请临时加时。」 |
| L5 | 委托 | 「这一条由智能插座执行，本机只发出请求。插座断开时这条失效，界面上会写明。」 |

文案规则集中在一处（`LAYER-09`）：状态句给出当前状态与恢复时刻；错误必须给出下一步；
说明放常驻位置，Toast 只留一句结论；鼓励语只来自写下它的那位家人（标注到人）。

## 5. 能力登记表与升层回路

```
Capability(id, tier: L0|L1|L1.5|L2|L3|L5, state: ok|degraded|missing|denied|unknown,
           evidence, probedAt, ttl, howToRaise, howToRevert, honestText)
```

- 当前层由登记表算出；界面、HTTP 状态与提示文案只读它。
- 探针在后台线程；`ttl` 过期即重探；取不到值时报 `unknown`。
- 升层与回退成对存在，回退保留题库、账本与任务进度。
- 授权状态由能力登记表定期探测；被系统收回时在应用画面内显示降级原因（F1、F2）。
- L5 的每次开 / 关各留一条审计事件。

## 6. 架构落点

- 内核产出 `CommitState`；层由 `enforcement` 单点推导：`tierFor(due)` 给形态层，与该身份强度的默认档取
  较低者得落层（`ARCHITECTURE.md §9`、`LAYER-07`）。单测覆盖「没有哪条结论被提到更高呈现强度」（`COMMIT-09`）。
- 无到期项时的状态层为 L1 / L1.5（§1 规矩 1）；`due` 的呈现档由 §3 的强度默认档与 `tierFor` 给出；
  题目浮层属 L2 / L3 的呈现；开机广播是 L3 的触发器；无障碍是可选判定加速器。
- 自启、悬浮窗授权、无障碍绑定等按事实显示，包含失败项（F1、F3、F10）。
- 出网目的地只有 `PRIVACY.md §2` 的清单；统计与遥测在本机；提示路径由 F2 决定（通知不可靠）。
- 设备可被随时卸载；需要物理停止观看时走 L5，由家庭自行配置。

## 7. 事实依据

- F1：部分固件在重启时清掉悬浮窗授权，因此能力状态必须定期重探。
- F2：电视形态下系统通知基本不可用，因此每层都需要应用内替代。
- F3：第三方应用没有可靠的开机自启通道，因此自启按事实描述。
- F12：「请求播放器暂停」的响应率按机型与播放器分档统计中；在数据到位前，`focused` 的描述保持为
  「本机会尝试让内容暂停，不响应时自动改为不打断模式」。
