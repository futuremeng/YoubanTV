# 建立约定（AGREEMENT）

规格条目在 [`../spec/AGREE.md`](../AGREE.md)，字段/类别/默认值/首启步骤的**数据**在
[`../contract/contract.json`](../contract/contract.json) 的 `agreement` 一节。这一页只写流程与取舍。

## 1. 一句话

**装完应用第一次打开要做的唯一一件必做事，就是把一份约定立起来。**其余条目（授权、探针、出网、
配对、内容包许可）都是可选的，未完成只降级不阻断（`ONBOARD-06`）。这条把「onboarding」从
"填资料"改成"立约定"——`docs/ONBOARDING.md` 那张清单是它的副产品，不是它本身。

## 2. 两条建立路径

| 路径 | 什么时候 | 问什么 | 依据 |
|---|---|---|---|
| 首次安装 | 第一次打开应用 | 六步全走（§3） | AGREE-01、AGREE-05 |
| 切换身份 | `PROFILE_SWITCH` 之后该身份还没有生效的约定 | 同样六步，**但设备条目不重复问** | AGREE-08、AGREE-09 |

约定按身份各立一组（AGREE-08）： kid / dad / mom 各自有一份 plan + 版本 + 签署记录，互不影响；
一份约定的收紧不会改掉另一份（AGREE-08），共意条目的"对方"可以是不同的人。

## 3. 六步（顺序与写意都在契约里）

| 步 | 问什么 | 不选时的默认 | 谁有权改 | 写了什么 |
|---|---|---|---|---|
| 1 | 这个身份叫什么、绑哪些内容包与大纲范围 | 必填 | 该身份 + `ruleEditor` | PROFILE 建立（`PROFILE-01`、`PROFILE-06`） |
| 2 | 这一档是谁（受众） | 必填 | 该身份 | `audience`（`PROFILE-02`） |
| 3 | 每天使用时长 / 约定线 / 运动段起点 | 契约 `agreement.defaults` 那一行 | 共意（`AUTO-07`） | `plan v1` |
| 4 | 时段与免题段 | 全天在时段内、无免题段 | 共意（`DAY-08`、`DAY-03`） | `plan v1` |
| 5 | 委托强度（约定字段编辑权在谁手里） | 协商式 | 该身份自己（`PROFILE-03`） | `strength` |
| 6 | 双方签署 | — | 双方 | `PLAN_SIGNED(v1)`（`AUTO-07`） |

**每一步都可以「先用默认」**（`agreement.firstRunEscape`）：中途退出也能用，被默认填着的条目标
「未签·默认」。这条是整个设计的承重墙：初始化不能是门槛。因此——

- 「未签」在界面上是一句状态句（L1 一条提示），**不是**弹窗、不是红点、不进周报、不打分、
  不做连续天数（AGREE-04、`ONBOARD-05`）；
- 未签署的版本不进运行版本、不写 `PLAN_SIGNED`（`COMMIT-08`、`AUTO-04`），旧版本继续生效；
- 「没签」绝不记成某个成员的违规，也不进任何统计（AGREE-06、`AGREE-10`）。

## 4. 改约定与收回

```
想改 → 动议（提出方/对象/条款/一句理由）→ 对方在自己界面受理（PROFILE-10）
     → 双方签署 PLAN_SIGNED(v+1) → 生效路径：增大当日生效、减小次日生效（D37、AGREE-07）
临时加时不动约定：它是当日约定线的偏移（extend，AUTO-03）
收回委托/编辑权属收紧 → 自下一份双方签署生效（AUTO-04、AUTO-09、AGREE-11）
```

## 5. 一条约定要能自证来历

界面上每条生效条目都能答出四件事：**给谁的 · 谁签的 · 什么时候签的 · 依据哪个条目**（AGREE-12）。
这一节随「我的数据」导出（`PRIVACY.md §1`）。做不到这一条，"约定"就退化成"设置项"。

## 6. 什么时候做

- **设计：这一轮已落**。条目在 `spec/AGREE.md`；数据在契约 `agreement`（字段类别、默认值表、六步、
  per-profile 规则、不许清单）；**默认值表从此只有一处**——原来 Ruby 写一份、Kotlin 又写一份，
  连「默认算不算在时段内」都只有一边写了，这正是对齐门要抓的那类（D45）。
- **实现：M3.5**，紧接 M3 收尾、在 M4（家庭面板）之前。三条理由：
  1. M4 的面板要显示「生效的约定条目 + 签署人与时刻」（AGREE-12），没有建立过程就没有可显示的东西；
  2. 设备端已有内核与事件账，`PLAN_SIGNED` / `PROFILE_SWITCH` 两类事件已经进得来，缺的只是"谁问、
     问几步、签没签"这条流程与按身份加载约定的那层；
  3. 再往后的 M5 / M5.5 都建立在"这台设备这一档受哪几条例约约束"之上。
- **这轮已经绿的部分**：`fixtures/agree.yaml` 15 道全过——默认档跑法与「默认·未签」、没签的版本
  不进在跑的那一版、**按身份各立一组约定**（`given.plans` + 切换时加载那一组的版本与签署状态）、
  改自己这一组不串到别人那一组。反证过：把「切换时加载那一组的版本」那一行去掉，AGREE-08 立刻红。
- **这轮又绿了一块**：「缺一份签过的约定」现在由**内核说出下一步**——契约 `nextAction` 多了 `agreement`
  这个取值，常驻那一栏的中文在 `commitState.panels`，档位仍是 L1 那一行。真机上验过可翻转：
  补一条 `PLAN_SIGNED` 事件，`nextAction` 归位、那一栏消失（`facts/DEVICES.md#F21`）。
- **首启那六步在设备上能走了**：确认键进流程，一屏一项，←→ 改、OK 下一步、返回上一步，
  最后一屏签署 → 账里落 `PLAN_SIGNED(v1)` → 「未签」那一栏消失（`facts/DEVICES.md#F23`，
  设备自检第 7 道 `setup`）。屏上问什么、有哪些可选，全部由设备上的内核从契约里给。
- **还没绿的部分**：切身份后屏上显示的是另一组约定（模型侧已绿，设备侧的切换入口还没有）；
  时段表这类遥控器改不了的字段仍是「按默认 + 写明去哪儿改」。
- **受理这一步在设备上有了**：挂着一条要受理的动议时，确认键就是那「一次受理」（`facts/DEVICES.md#F22`）；
  没挂着东西时账上一个字都不写——按键不许变成回执或第二次提醒（AGREE-11、D34）。

## 7. 明确不做的

时长兑换题目（D24、D31）、签到与连续天数与徽章（D31）、把"父母"写成特权身份（D33）、
把"没签"记成违规、装机默认全开设备条目或出网（`ONBOARD-06`、`ONBOARD-08`）——这份清单也写进了
契约 `agreement.never`，契约引用门会卡禁止字段。
