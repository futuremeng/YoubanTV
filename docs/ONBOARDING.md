# 设备待确认清单（Onboarding）

> 这台设备上「约定怎么立」是另一件事，写在 [`AGREEMENT.md`](AGREEMENT.md)（条目 `spec/AGREE.md`）：
> 装完应用第一次打开的必做只有一件——把一份约定立起来；切换身份就是换一组约定（AGREE-08）。
> 本页那张清单是它的副产品：哪些确认还没做、由谁在哪一处确认、没做时按什么保守档落。

一台设备一份清单。它只回答一件事：**这台设备上还有什么没确认、由谁在哪一处确认、没确认时按什么
保守档落**。规则与功能与清单无关——清单不改变任何判定（`ONBOARD-05`）。

条目 id 形如 `<装配>.<类别>.<项>`，装配 ∈ `tv` / `mobile`，类别 ∈ `auth`（系统授权）、`probe`（能力探测）、
`agree`（约定与签署）、`egress`（出网）、`role`（角色交接）、`pack`（内容与许可）、`time`（时间完整性）、
`device`（外部设备与配对）。id 是稳定的：只增不改不删，退役条目留在表里标注退役。

## 1. 原则（四条）

1. **派生，不入库**：条目与状态从事件、`capability` 登记表和 `roles` 现值算出，没有「清单项」表（`ONBOARD-01`）。
2. **只增不催**：一台设备一台设备、一个成员一个成员地扩充；提示只有 L1 一条，不递进催促（`ONBOARD-05`）。
3. **未完成只降级**：取该能力最保守的可用档并写明原因，绝不阻断（`ONBOARD-06`）。
4. **谁的事谁那侧做**：需要对方确认的条目，受理只发生在对方自己的界面（`ONBOARD-04`、`PROFILE-10`）。

## 4. 扩充触发（随加入进来的东西）

条目只能由下表产生（`ONBOARD-03`）。要加新的触发，先改这张表。

| 触发 | 新增条目 | 备注 |
|---|---|---|
| 新成员加入家庭 | 该成员每台已装配设备上的 `*.agree.plan` + `*.agree.slots`；电视端加一条「命名与内容绑定」 | 模式命名与内容绑定完成即算这条勾掉（`PROFILE-01`、`PROFILE-06`） |
| 新设备加入 | 该装配的**全部固定项**（§2 / §3） | 首启引导就是这些条目的前五项（暂定值，`LAYER-02`、`DECISIONS.md`） |
| 成员从电视端扩到手机端（或反之） | `mobile.probe.crossDevice` + 该设备的 `*.agree.plan` | 同一身份跨设备并集需两端都有事件 |
| 角色移交（`ruleEditor` / `keyHolder`） | 一条 `tv.role.holder` / `mobile.egress.state` | 两次确认，交接双方各一次（`AUTO-09`） |
| 身份删除 | 一条归档确认 | 面板写明留了什么（`PROFILE-08`） |
| 内容包加入或更新 | 一条 `tv.pack.license` / `mobile.pack.license` | 许可不过则该包不取题（`PACK-01`） |
| 新增出网目的地 | 对应 `*.egress.*` 一条 | 地址先在 `PRIVACY.md §2` 登记，再进清单 |
| 系统更新或重启 | §2 / §3 里所有 `probe` 与 `auth` 类条目重开 | 探针重跑；证据时间早于最近一次重启即 `pending`（`ONBOARD-07`） |
| 系统时间被改 | `tv.time.clockDrift` / `mobile.time.clockDrift` | 核对完成后自动勾掉（`DAY-07`） |
| 摄像头通道被开启 | `mobile.device.calibrate` | 自检未过即保持 `pending`，通道保持关 |
| L5 设备配对变化 | `tv.device.pair` | 未配对则 L5 条目 `notApplicable`（不是 `pending`） |

## 5. 界面与呈现

| 位置 | 内容 | 层 |
|---|---|---|
| 电视引导页 | 首次开机时的前五项（授权 + 命名 + 时段），一步一项 | L1 → L2（只请求当前层必需的最小权限集） |
| 电视「设备」页 | 本设备清单：分组（授权 / 探测 / 约定 / 出网 / 内容 / 时间 / 外部设备），每条一行 | L1 页内；待确认条数只在页内显示 |
| 手机「设备」页 | 本机清单（§3） | L1 页内 |
| 家庭面板「设备」页 | 每台设备一份清单 + 完成度 + 每条的确认人与时刻 | L1；面板不弹提示 |
| 学习页 | **不出现**清单条目，只在被这条约定影响时给一句状态句 | L1.5 |

呈现纪律：清单不进周报、不打分、不做成就（`ONBOARD-05`）；`unknown` 与 `pending` 的文案是状态句加
下一步（`LAYER-09`），例如「这台机器的暂停响应还没探到，题目按边看边做呈现；要探测就跑一次」。

## 6. 回看与导出

清单状态是账本的一部分：面板可回看每条的确认人、时刻与证据指针（`AUTO-02`）；导出「我的数据」时
清单以一节列出（`ONBOARD-10`、`PRIVACY.md §1`）。清单本身不作为对某个成员的评价依据，也不进成长记录。
