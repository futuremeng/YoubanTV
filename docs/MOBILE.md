# 手机端（陪伴端）

## 1. 角色

手机端是一个**完整的陪伴端**：它承载一个激活身份，运行与电视端同一套机制
（[`PROFILES.md`](PROFILES.md)、[`COMMITMENTS.md`](COMMITMENTS.md)）。

| 面 | 内容 | 实现位置 |
|---|---|---|
| 学习面 | 约定状态、`focused` / `ambient` 题目、补一补、主观题自评与修订、动议与待受理、周报 | `core/*`（同一份代码） |
| 身体面 | 本机姿态计次、运动邀请、作为电视端的传感器端 | `device/sense`、`sensor/` |
| 共在面 | 共看安排与邀请、在场提示、家人原话送达 | `device/presence`、`net` |

手机端是**单用户场景**：一次一个人，没有电视端那层模式切换（`PROFILE-10`）。
管理端仍是浏览器面板（[`ARCHITECTURE.md §5`](ARCHITECTURE.md)）；任何成员的入口都只是面板的一个响应式视图，
能改什么由**角色**决定（`AUTO-10`）而不是由身份决定，没有独立的「管控」功能面；手机上的学习面只存本人
那一份账与待受理动议。
层取值与电视端相同（`L0 / L1 / L1.5 / L2 / L3 / L5`），但手机端只取用应用内的
L1 / L1.5 / L2（`LAYERING.md §1` 规矩 4）。

待确认清单在手机上只有本机那一份（`ONBOARDING.md §3`）：节律自检、跨设备时长合并、通知可达性、
出网开关的只读状态；`mobile.device.calibrate` 在用户尝试开启摄像头通道时进入清单，自检未达标则该条目保持
待确认、通道保持关（D36、`SENSE-02`）。

## 2. 共在面

| 功能 | 做什么 | 数据 |
|---|---|---|
| 共看安排 | 在 `dayPlan.slots` 里放 `co-watch` 段；双方确认后进入静默运行（计时与题目按该身份规则照常，提示收敛） | 时段条目，本机 |
| 共看邀请 | 一方发起一条 `coWatch` 动议（`AUTO-03`），另一方在自己的界面一步受理或婉拒；受理后两台设备显示同一状态条 | 文本 + 时间戳 |
| 原话送达 | 家人写的句子**原样**送达，来源标注「妈妈写的」；应用不加自己的语气 | 文本，经家庭内路由 |
| 在场提示 | 该身份 `aloneMs` 进入 `engaged` 档时，向其他家庭成员的设备发一条事实提示：「他独自看了 1 小时 10 分」 | 时长与身份名 |
| 远程共看 | 跨城市的同步观看需要一条信令路径。当前实现范围：家庭局域网内直接建立；跨城需家庭自架可选信令端点 | 见 §5 |

`presence` 形态与 `inviteTier` 邀请规则见 [`COMMITMENTS.md §4b`](COMMITMENTS.md) 与 `SENSE-07`；显示给使用者的对偶量是
`withMs`（今天一起看了多久）。

## 3. 身体面

- 计次口径与电视端一致：节律计数、`counted` / `ambiguous` / `rejected` 三态；对计次判定有异议时提一条
  `cancelTask` 动议（`COMMIT-03`、`AUTO-03`）；
  计次只写 `ROUND_DONE` 入账，不兑换也不增减观看时长（`COMMIT-05`）。
- 姿态取值只有**节律与次数**：关键点在内存内逐帧处理，落盘只有计数结果（`SENSE-01/02`）。
- 项目分档：孩子（开合跳、深蹲、原地跑）、大人（快走、拉伸、力量组）、老人（坐姿操、慢走、平衡练习）。
  老人的平衡项目带安全约束条目：坐位起始、需有支撑物在旁、单次时长上限（`SENSE-05`）。
- 话术取即时的身体效果（「身体先醒过来」），不含姿态或健康结论（`SENSE-03`）。
- 手机的传感器选择顺序：无模型信号（加速度计计节律）→ 摄像头姿态（可选，默认关，需标定）→ 手动确认。
  三条路共用同一入口，计次逻辑与信号源无关（F4、F13）。

## 4. 学习面在手机上的差异

| 项 | 取值 |
|---|---|
| 默认参与形式 | `ambient`（手机上独看居多，暂停代价高） |
| 题目形态 | 单手可答；`focused` 题只在竖屏整屏时出现 |
| 呈现层 | 只用应用内：L1 角标 / L1.5 状态条 / L2 题目呈现时机；不用系统悬浮窗与开机广播（`LAYERING.md §1` 规矩 4） |
| 字号 | 8 档阶梯 + `大字` 令牌（整体上移一档、对比度提高、四键收敛） |
| 时段与额度 | 与同一身份在电视上的账**合并累计**（见 §5） |

## 5. 同一身份在多台设备上

- `WATCHED` 事件带 `device` 字段；某身份的当日时长是**各设备事件的并集**，重叠区间去重
  （`PROFILE-04`、`DAY-01`）。
- 约定状态按身份计算，与设备无关；`due` 的呈现落在**当前有前台会话的那台设备**上。
- 跨城设备之间需要一条信令路径。零服务端的取舍：
  1. 默认只在家庭局域网内建立（设备互相发现，同一套配对与 scopes）。
  2. 跨城由家庭自架可选信令端点（开源、单文件、只转发密文与时间戳），面板里显示它的存在与用途。
  3. 没有信令路径时，跨设备共看功能**显示为不可用**，本机功能照常。

## 7. 与旧设计的差异

| 旧 | 现在 |
|---|---|
| 手机端 = 配套管控端（远端开关、锁定、查看另一台设备） | 手机端 = 陪伴端：承载自己的身份与约定；管理能力留在面板，且管理动作是**设定约定**而非远端操控 |
| 体感姿态识别 = 另一台设备的计数器 | 体感是手机端的一等能力，也是全项目共用的传感器端角色 |
| 大人与老人用手机只为「管理孩子」 | 大人与老人用手机作为自己的使用者端 |
