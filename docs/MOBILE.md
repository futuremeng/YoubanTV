# 手机端（陪伴端）

## 1. 角色

手机端是一个**完整的陪伴端**：它承载一个激活身份，运行与电视端同一套机制
（[`PROFILES.md`](PROFILES.md)、[`COMMITMENTS.md`](COMMITMENTS.md)）。

| 面 | 内容 | 实现位置 |
|---|---|---|
| 学习面 | 约定状态、`focused` / `ambient` 题目、补一补、主观题自评与修订、动议与待受理、「这段时间的账」那一页 | `core/*`（同一份代码） |
| 身体面 | 本机姿态计次、运动邀请、作为电视端的传感器端 | `device/sense`、`sensor/` |

手机端是**单用户场景**：一次一个人，没有电视端那层模式切换（`PROFILE-10`）。
管理端仍是浏览器面板（[`ARCHITECTURE.md §5`](ARCHITECTURE.md)）；任何成员的入口都只是面板的一个响应式视图，
能改什么由**角色**决定（`AUTO-10`）而不是由身份决定，没有独立的「管控」功能面；手机上的学习面只存本人
那一份账与待受理动议。
层取值与电视端相同（`L0 / L1 / L1.5 / L2 / L3 / L5`），但手机端只取用应用内的
L1 / L1.5 / L2（`LAYERING.md §1` 规矩 4）。

待确认清单在手机上只有本机那一份（`ONBOARDING.md §3`）：节律自检、跨设备时长合并、通知可达性、
出网开关的只读状态；`mobile.device.calibrate` 在用户尝试开启摄像头通道时进入清单，自检未达标则该条目保持
待确认、通道保持关（D36、`SENSE-02`）。

## 2. 共在面：**这三样不做**（`AUTO-17`、D79）

共看安排与共看邀请、在场提示、家人原话的送达——**都不做**，也没有留「改走面板」这条后门：
契约里没有 `POST /api/cowatch`，也没有 `POST /api/messages`（两条登记在 `retired.endpoints`，出现即红）。

- 动议种类里没有共看（`motion.kinds`），`dayPlan.slots` 里没有 co-watch 这类段，面板里也没有那一页。
- 「某人独自看了多久」不发到别人的设备上；**「一起看了多久」这个对偶量因此没有来源，不做**
  （原 `COMMITMENTS.md §4b` 划出范围；依据侧的张力如实记在 `D79`）。
- 家人写的句子仍然**标注到人**（`LAYER-09`——谁写的就署谁），但**撰写入口是面板**，不做设备之间的送达。
- 手机与电视之间的关联**只剩体感与视觉两件事**（`SENSE-06`）。

## 3. 身体面

- 计次口径与电视端一致：节律计数、`counted` / `ambiguous` / `rejected` 三态；对计次判定有异议时提一条
  `cancelTask` 动议（`COMMIT-03`、`AUTO-03`）；
  计次只写 `ROUND_DONE` 入账，不兑换也不增减观看时长（`COMMIT-05`）。
- 姿态取值只有**节律与次数**：关键点在内存内逐帧处理，落盘只有计数结果（`SENSE-01/02`）。
- 项目分档：孩子（开合跳、深蹲、原地跑）、大人（快走、拉伸、力量组）、老人（坐姿操、慢走、平衡练习）。
  老人的平衡项目带安全约束条目：坐位起始、需有支撑物在旁、单次时长上限（`SENSE-05`）。
- 话术取即时的身体效果（「身体先醒过来」），不含姿态或健康结论（`SENSE-03`）。
- 手机的传感器选择顺序：无模型信号（加速度计计节律）→ 摄像头姿态（可选，默认关，需标定）→ 手动确认。
  三条路共用同一入口，计次逻辑与信号源无关（F4、F13）。

## 4. 学习面在手机上的差异

| 项 | 取值 |
|---|---|
| 默认参与形式 | `ambient`（手机上独看居多，暂停代价高） |
| 题目形态 | 单手可答；`focused` 题只在竖屏整屏时出现 |
| 呈现层 | 只用应用内：L1 角标 / L1.5 状态条 / L2 题目呈现时机；不用系统悬浮窗与开机广播（`LAYERING.md §1` 规矩 4） |
| 字号 | 8 档阶梯 + `大字` 令牌（整体上移一档、对比度提高、四键收敛） |
| 时段与额度 | **只算这台设备上的账**（`DAY-10`）：与电视端不合并、不做并集（见 §5） |

## 5. 一台设备一本账

**计时不跨设备合并**（D77）：某身份的当日时长按构造就是**这台设备上**的数，界面上那行数字不带「合计」那句。

- 模型里没有「把两台的段相加」这个入口：过滤只在一处（`core/ledger` 的 `for_profile`），
  面板那种「各列一行」走 `by_device`——那是**列出来**，不是**合起来**（`DAY-10`）。
- 另一台设备看了多久，就在另一台那一页说另一台的数；要同时看两行，就在面板上各列一行。
- 取舍写在 `DAY-10`：并集需要一个可信的时间源，而改表跳动这条靠单调钟佐证（`DAY-07`）——
  把一台的墙钟问题变成两台的合计问题，不划算。
- **手机与电视之间的直连只为两件事**：体感与视觉（`SENSE-06`）。这条通路不承载计时、不承载判定输入，
  也不承载另一台的那本账；过界的只有计数与判定，画面与关键点不出手机（D77）。
- 共看安排、在场提示、家人原话这三样**不做**（`AUTO-17`、D79）：不在直连上，也不在面板那套 API 上。

## 6. 手机端不做的功能

| 范围外 | 依据 |
|---|---|
| 使用时长上限、应用阻断、锁机 | [`research/EVIDENCE.md §1`](research/EVIDENCE.md)、[`research/MOBILE-COMPANION.md §1`](research/MOBILE-COMPANION.md) |
| 位置、通讯录、短信、通知读取 | [`PRIVACY.md §5`](PRIVACY.md) |
| 拟人角色与情感声称；以孤独为可见指标 | [`research/EVIDENCE.md §5 §7`](research/EVIDENCE.md) |
| 高频通知、签到、连击、排行 | [`../spec/AUTONOMY.md`](../spec/AUTONOMY.md)（AUTO-05、AUTO-13） |
| 姿态/健康诊断结论、康复承诺 | [`research/MOBILE-COMPANION.md §4`](research/MOBILE-COMPANION.md) |
| 摄像头常开、画面存盘或出设备 | [`PRIVACY.md §1`](PRIVACY.md)、`SENSE-02` |

## 7. 与旧设计的差异

| 旧 | 现在 |
|---|---|
| 手机端 = 配套管控端（远端开关、锁定、查看另一台设备） | 手机端 = 陪伴端：承载自己的身份与约定；管理能力留在面板，且管理动作是**设定约定**而非远端操控 |
| 体感姿态识别 = 另一台设备的计数器 | 体感是手机端的一等能力，也是全项目共用的传感器端角色 |
| 大人与老人用手机只为「管理孩子」 | 大人与老人用手机作为自己的使用者端 |
