# 产品定义

## 1. 形态与身份

一台被控的 Android 设备（电视 / 盒子）+ 家庭成员各自的 Android 手机。手机端是完整的陪伴端，与电视端
共用同一套机制（[`MOBILE.md`](MOBILE.md)）。数据与判定在家里这台设备上，无需服务器。

全家共用这台设备，靠**身份切换**区分当前使用者。身份决定题库、知识大纲、运动项目与默认值；
功能集合对所有身份相同（[`PROFILES.md`](PROFILES.md)）。

| 身份 | 需要 | 提供 |
|---|---|---|
| 孩子 | 知道约定是什么、走到哪一步、可以提出调整 | 状态三件套（规则 / 差多少 / 下一步）、同一份账本视图、动议入口、学科题库与大纲 |
| 大人 | 自主安排时间与练习 | 同一套机制：运动项目与自管强度、「这段时间的账」那一页；题是**可选的**（装了绑到这一档的包就有，不装也不被追问）（`PROFILE-11`、D76） |
| 老人 | 白天正常观看，安静运行 | 同一套机制的另一组默认值（约定线很宽、免题段覆盖全天）+「大字」呈现令牌 |
| 受托成员（`ruleEditor`，可轮值） | 设一次就稳定运行；随时看得见每个人把自己评成什么样 | 意图式规则、计划模拟器、按身份的账本与掌握视图；自评结果的**查阅与修订**与动议的受理（`AUTO-15`、`AUTO-03`） |
| 手机上的任何人 | 独看时也想知道约定在哪、想被邀请动一动或一起看 | 同一套机制的手机装配：学习面 + 身体面 + 共在面（[`MOBILE.md`](MOBILE.md)） |
| 扩展者 | 加玩法、加题目来源 | 内核一处判定，其余是投影与适配器 |

## 2. 范围

**范围内**：本机账本与约定引擎、题库与知识大纲、运动计次、家庭面板（**1.0 只有那一屏只读面板与那张页表，界面推到 2.0**，D80）、设备待确认清单（`ONBOARDING.md`）、内容包、**被系统作为开机启动项拉起 + 加载完即交回前台 + 拉起用户指定的那一个应用**（`LAYER-14`、`ONBOARD-11`、`ONBOARD-12`、D81）、可选 AI 出题与 AI 批
（自评与查阅修订）、可选伴看上下文、可选外部设备协同、**电视角上那只小宠物**（只在 L3 那一角、无养成数值、默认关，`PET-01..08`、D83）。

**范围之外**：云服务与账号体系、跨家庭同步、监控类能力、广告与第三方统计、排行与打卡、
设备所有者 / Kiosk / Lock Task、强制更新、应用卸载保护、任何阻断观看的路径、**共看与在场提示与家人原话的送达**
（设备之间的关联只有体感与视觉两件事，`SENSE-06`、`AUTO-17`、D79）；
**宠物的养成数值与由行为推出的状态**——亲密度、心情、饥饿、等级、成长、待领取、回访连击那八个名字一个都不许有，
「它想你了」「它有点难过」这类话界面上一个字都不许出现（`PET-01`、`PET-02`）。

## 3. 核心模型

**一本账**：只追加的事件流（`WATCHED` / `DONE` / `ANSWER` / `ROUND_DONE` / `OVER` / `MISSED` /
`PLAN_SIGNED` / `PLAN_CHANGE` / `PROFILE_SWITCH` / `MOTION` / `MOTION_SETTLED` / `MOTION_UNANSWERED` /
`REVISION` / `ROLE_CHANGE` / `REMOTE`（`MOTION*` 是动议的提出与受理或超时，`AUTO-03`；`REVISION` 是对自评
结果的改判，`AUTO-15`；`ROLE_CHANGE` 是角色的移交与收回，`AUTO-09`；`REMOTE` 是设备控制的留痕，
`COMMIT-07`），其余一切都是投影。派生量：
`watchedMs[profile]`（今天看了多少）、`roundsDone[profile]`（今天完成几组，由事件数得出）。

**约定状态**（唯一结论结构，实现在 `core/commit` 一处）：

```
CommitState { status: honored|due|overdue, activeProfile, planVersion,
              due: { kind: quiz|exercise|free, mode: focused|ambient,
                     deficit, window, howToAsk, ruleId, nextAction }? }
```

| status | 条件 | 呈现 |
|---|---|---|
| `honored` | 在免题段内，或约定要求已满足 | 角标显示剩余；完成时一句状态确认，星与掌握进度入账 |
| `due` | 做题或运动的约定到期未达成 | 按 `mode` 呈现题目；`ambient` 不打断，`focused` 请求播放器暂停 |
| `overdue` | 约定时长用尽仍在看 | 状态条显示超出时长；协议页与「这段时间的账」那一页里可见 |

**到期项有哪几类**按受众挑一次（`dueKinds`，写在 `agreement.defaults` 那几行里，位点只有一处）：孩子的约定项
含题目与运动，大人只含运动，老人的两样都不含——题对后两档是可选的内容，不是判定的一部分（`PROFILE-11`、D76）。

约定线 `allowance` 按身份各一套（上学日 / 周末与节假日两套默认值），是**目标线**：超出的时长记 `OVER`，
呈现继续照常。做题与运动的完成只进事件与星 / 掌握进度，**不发放也不兑换时长**（`COMMITMENTS.md §2`）。
跨身份的时长各自记账；**同一身份在两台设备上也各自记账**——界面上那行数字按构造就是这台设备的数，
两行就各列一行，谁也不并进谁（`DAY-10`、D77）。未选身份时计时会话以 `profile=none` 记录，判定直接取 `status=honored`、`due=null`
并提示选择身份（`COMMIT-11`）。

**词汇**：`status`、`due`（到期项）、`mode: focused|ambient`（停下来做 / 边看边做）、
`pauseMs`（暂停时长，冻结段不计入 `watchedMs`）、「补一补」、「守约」。

## 4. 规则模型

| 层 | 内容 |
|---|---|
| L0 预设 | 按身份选协商强度（陪伴式 / 协商式 / 自管式）＋作息预设（放学后 40 分钟、晚饭后 1 小时、周末宽松、严格） |
| L1 意图 | 每天约定时长、免题段、运动段起点与项目、时段（半小时格子）、达标正确率、每组与每星的星数 |
| L2 专家 | 间隔重复、补一补阈值、答题范围、跨年级回溯、AI 批与修订的评分标准、联动令牌 |
| 家庭协议 | 周计划双方签署，改动需对方同意；未签署的计划不生效 |

**自管字段**（`AUTO-14`）：组数、每组题量、每次任务的题目数上限、补一补是否先补完——由该身份自己设定，
与协商强度档位与 `audience` 无关；面板只显示与回看，不作他人的修改入口或强制门。

推导量只显示、不输入：`due.window`、需要的组数、生效组数（`DAY-05`）。
**计划模拟器**：改任一字段，底部时间线实时重算，保存前所见即引擎将执行的。

## 5. 学习循环

- 任务 = 一个实体三种目标类型：`round` 按组闯关 / `streak` 连续答对 / `free` 自由练习；
  规则在任务开始时快照，收紧的规则自下一任务生效，放宽立即生效。
- 选题顺序：范围 → 优先级队列（间隔重复到期 → 补一补池 → 自适应新题 → 范围内随机）→ 难度阶梯 →
  去重（本任务内不重复、同知识点每任务最多 2 题）→ 后备实时出题。
- 知识点状态机（词表与 `ASK-03` 同一套）：`unseen 新接触 / learning 学习中 → shaky 需巩固 / weak 薄弱 /
  mastered 已掌握`。进 `mastered` 需同点连对 3 题（包内不足 3 题时答对全部即掌握）；
  答错先出 1 道 `basic` 确认题，确认题对 → `shaky`，确认题错 → `weak` 并沿硬先修向下找。
- 难度 ↔ 星级：基础 1★ / 标准 2★ / 挑战 3★ / 进阶 4★（进阶按「离目标最近」取），5★ 留给任一成员自编题。
  跨学段回溯默认关。
- 间隔重复用 SM-2 简化式；开关只切换抽题方式，进度保留。
- 补一补池：跨天与跨重启保留，答错落盘，池上限 20 道，奖励只影响星级与掌握状态；
  是否先补完再开新任务由该身份自己定（自管字段，`AUTO-14`）。
- 选题细节见 [`../spec/ASK.md`](../spec/ASK.md)。

## 6. 内容

- 题目 schema v3；客观题按答/错判定，填空忽略大小写、首尾空白、全角半角；多选需全对；`$…$` 本地渲染。
- `verify` 是求值：算出一个值再比较，语法白名单 + 求值超时 + 回落文本比对。
- 内容包 `.qpack`：manifest 含许可（SPDX）、署名、来源、签名、校验和、`audience`、`presentationHints`。
  APK 自带 CC0 种子包；第三方题库一律以包形式安装与卸载；许可校验失败即拒装（`PACK-01/02`）。
- 实时出题在后备时启用，默认只在内存，界面标注来源，任一成员点「收下这题」才入库（来源标注到人）。
- 成人、老人、孩子的题库与知识大纲都是数据：新增一个 audience 只需新包与内容绑定。

## 7. 协商强度与协议

五条设计原则：**配额只由约定来（完成只入账，不兑换时长）**；**账本与规则对所有人同一份视图**；**周计划共同签署**；
**能力对所有身份相同，差异只在内容与默认值**；**学习参数归本人**（组数与补一补节奏由该身份自己定，
**他人只能经签署与动议改变它**（`AUTO-14`）。

| 强度 | 约定字段编辑权在谁手里 | 该成员手里有 | 对方（受托方）手里有 |
|---|---|---|---|
| 陪伴式 | **委托**给另一位成员（`ruleEditor`）：可轮值、可随时收回、全程留痕 | 动议、自己的进度与小目标、自管字段（组数 / 每组题量 / 题目数上限 / 是否先补完） | 约定字段全部 + 自管字段的只读视图 |
| 协商式（默认） | 双方共同持有，周计划双方签署 | 提案、签署、动议、自设小目标、自管字段 | 约定字段全部 + 否决（附理由，双方同等）；自管字段只读 |
| 自管式 | 该成员自己定 `dayPlan` | 约定字段编辑权、自管字段、账本与「这段时间的账」那一页 | 收回（留记录）、同一页的只读视图 |

强度由身份自己选择，与年龄无关、无需批准；切换强度时全部功能保持可见（`PROFILE-03`）。
收紧的改动在新签署前不生效（`AUTO-04`）。

六条规则：A1 结论可解释；A2 一本账两份视图；A3 动议与修订通道（受理、婉拒与改判都附理由并留档）；A4 收紧不追溯；
A5 文案与激励规则（见 `LAYER-09`）；A6 每个人对自己数据的权利（可查、可清除自己的记录，留审计事件）。

违约的后果限于四项：`MISSED` 落账、补一补池 +1、次日协议议题、`overdue` 状态条（`COMMIT-06`）。
暂停与解除暂停由已受理的动议触发，其效果是状态与提示，播放继续（`COMMIT-07`、`AUTO-16`）。

## 8. 呈现与执行层

**伴**指这台设备会把约定讲清楚：结论带 `ruleId` + 差多少 + 下一步；受理动议；按协议交出编辑权（`AUTO-07`、`AUTO-09`）。
名称「有伴」不含「电视」二字，与在俗 IPTV 项目的检索区隔。

层的取值只有 `L0 / L1 / L1.5 / L2 / L3 / L5`；`L4` 是保留空位。层只描述**侵入度与呈现时机**。
内核没有 `enforcement` 概念，执行层由 `enforcement` 单点推导（`ARCHITECTURE.md §9`）。
**默认分两条线**：无到期项时的状态层为 L1 / L1.5（与强度无关）；有 `due` 时的呈现档随协商强度取默认档——
陪伴式 L3 / 协商式 L2 / 自管式 L1（`LAYERING.md §1`、`§3`）。

| 层 | 承载的结论 |
|---|---|
| L1 提示 | 约定进度（只有角标剩余时）、**待受理动议**（一条提示，可忽略）、自管强度下自己改当日约定线（留痕） |
| **L1.5 状态提示**（默认） | **已受理的暂停与解除**、`overdue` 状态条——提示条 + 角标 + 一次通知，30 秒收起 |
| L2 呈现时机 | `focused` 题目：请求播放器暂停 + 浮层，答完恢复；补一补；未签署协议时任务不开始 |
| L3 应用外浮层 | 电视端：角标与 `ambient` 题在离开本应用后仍可见；开机广播触发；浮层在内容角落，避让字幕区。手机端只用应用内呈现 |
| L5 外部协同 | 由外部设备执行断电 / 切源 / 限速；**只由已签署的时段规则触发**，动议不能命令外部设备（`AUTO-16`）；外部设备不可达时该条失效并在界面显示 |

设备可被随时卸载；关于页写明这一点。需要物理停止观看时走 L5，由家庭自行配置与配对。

文案与激励规则见 [`../spec/LAYER.md`](../spec/LAYER.md)（措辞条目为 `LAYER-09`）与
[`../spec/AUTONOMY.md`](../spec/AUTONOMY.md)；数据与隐私见 [`PRIVACY.md`](PRIVACY.md)。
