## 未决的技术问题

1. **事件账的读放大**：投影表在同一事务内维护；需实测一天几千条事件时首页与状态端点的耗时。
2. **成员令牌与角色的绑定**（D33 / D35 后重写）：长期令牌（配对一次，绑定设备）还是每次动议临时签发。
   临时签发贴合 A6，多一次交互；角色不得从令牌或 `audience` 推导（`PROFILE-02`）。
3. **自管强度下 `dayPlan` 的字段范围**：自管字段四项已定（D31、`AUTO-14`），不进入双方签署范围；
   剩下的只有时段与家庭协议字段在共同签署下的边界，需确认与 `AUTO-04` 的交界。
4. **收紧规则的生效边界**：时段变更与零点刷新的交互——`dayPlan` 在跨零点前 5 分钟内收紧时顺延到明天。
5. **契约生成的构建耦合**：面板与设备端各生成一次会漂移；需要一条 `make contract` 产出 + CI 校验生成物时效。
6. **`focused` 的默认值**：依赖 F12（各机型暂停响应率）实测结果分档。
